## Acceptance boundary

The source candidate removes the three application-imposed model limits, adds streaming evidence capture, and separates the Worker dispatcher from a Task Scheduler executor entrypoint. The dispatcher integration test verifies that it returns with a queued manifest but no STARTED receipt before a process marker exists; after exact process-marker readback it publishes STARTED, and it never calls the injected model runner. Executor tests validate the task contract, manifest idempotency, identity mismatch, and terminal evidence semantics. These are local source tests, not a registered-task or host acceptance.

R10 isolated the earlier `0x8007010B` / `0x00000001` startup failures to `CODEX_MSIX_APPDATA_ALIAS_PATH_MISMATCH`: the Codex-visible AppData alias was not the physical path accessible to the Task Scheduler run identity. Using the physical Documents path, R10 passed a PT15M baseline, a single-variable PT0S experiment, and a 967-second, 150-sample synthetic run; no target black windows were observed. All disposable test tasks were removed. This confirms PT0S capability and the path root cause, not the final executor architecture or production acceptance.

The live five-minute dispatcher remains on its existing task with `PT15M`; no production task or `HiddenWorker.vbs` was changed. The installed Worker has no executor descriptor, and no dedicated Executor identity, task, ACL, separate provider profile, or model authorization is installed. Consequently this candidate cannot dispatch a model job on this host. The `PT15M` limit is not removed from the live dispatcher; the candidate executor's `PT0S` contract remains unregistered and untested on the host.
